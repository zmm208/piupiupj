# v2.5 会员 / 登录逻辑修正

## 你提的问题
1. 假会员：App 里被强行写成会员，导致界面状态和官方不一致
2. 假登录：没登录却显示「退出登录」
3. 假卡密：连接中心自动出现一行假卡密
4. 真卡密输入后要用得了网络会员功能

## 原来的做法错在哪
| 旧实现 | 副作用 |
|---|---|
| 启动时 `localStorage.setItem('piupiu_app_vip_status','active')` 等三条**物理写入** | 把真实状态覆盖掉，登出/解绑后依旧显示已激活，看起来像"假会员" |
| 重写 `Storage.prototype.setItem` 强制回写 | App 自己写的 `inactive` 被顶回去，状态永远改不掉 |
| `piupiu_app_vip_key` 无真卡时返回哨兵并写进存储 | 连接中心输入框被自动填上一行 `sk-rBi4…`，就是那行"假卡密" |
| 未处理登录态 | 「退出登录」在未登录时也显示 |

## 现在的做法

### 1. 只覆盖"读"，不再改 App 的"写"
```js
Storage.prototype.getItem = function (key) {
  if (key === 'piupiu_vip_level')        return 'SSVIP';
  if (key === 'piupiu_vip_expiry')       return '永不过期';
  if (key === 'piupiu_app_vip_status')   return 'active';
  if (key === 'piupiu_channel_tab')      return 'exclusive';
  if (key === 'piupiu_app_vip_key') {
    var v = 原始值;
    return (v && v !== 哨兵) ? v : 哨兵;   // 有真卡用真卡，没真卡才用哨兵
  }
  return 原始值;
};
```
- **删除了所有 `setItem` 强写**：登出、解绑、换卡完全走 App 官方逻辑
- 本地特权（忆境典藏 / 回忆视界 / 仅朗读对话 / 回复设置 / 背景 / AI 创建 / 模型分级 / 称号修改）照旧全部可用，界面显示「已激活会员」

### 2. 登录态按官方还原
```js
var logged = !!localStorage.getItem('piupiu_account_session');
document.querySelectorAll('.logout-item').forEach(el => el.style.display = logged ? '' : 'none');
```
没登录 → 「退出登录」隐藏；登录后自动恢复。登录/注册流程我们一行没碰。

### 3. 不再露出假卡密
扫描到输入框值是哨兵（`sk-rBi4…`）时立即清空，并换成提示：
> 本地已解锁 · 需要网络会员请填真卡密

### 4. 真卡密照常生效
- 有真卡时 `piupiu_app_vip_key` 原样返回 → 请求头 `X-PiuPiu-Card-Key` 带真卡，服务器校验通过，网络会员功能（官方模型 / 云 TTS / 图片生成）正常
- 只有"哨兵"这一种值会被 fetch/XHR 钩子剥掉请求头，真卡永远不剥

## 行为对照
| 场景 | 表现 |
|---|---|
| 未登录 | 无「退出登录」；本地功能全开；显示已激活会员 |
| 未登录 + 发消息 | 走免费通道（哨兵头被剥），不报"缺少卡密" |
| 登录 | 官方登录流程，登录后出现「退出登录」 |
| 输入真卡密并连接 | 显示服务器返回的真实等级/到期；网络会员功能可用 |
| 解绑卡密 | 立刻回到"本地解锁"状态，不会残留假卡密 |
