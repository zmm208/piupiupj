# v2.6 「Unexpected token 'd', data: {ch…」修复

## 报错含义
```
Unexpected token 'd', "data: {"ch"... is not valid JSON
```
App 在对响应做 `JSON.parse`，但拿到的是 **SSE 文本**（以 `data:` 开头）。

## 原因
上一版为了过滤思考链，我把自定义请求一律改成非流式，然后**无论调用方要什么都回 SSE**：

```js
obj.stream = false;             // 请求侧：确实应该非流式
return ppSSEResponse(text);     // 响应侧：错，这里一律 SSE
```

App 里有些调用是 `stream:false` 的（比如自动摘要、记忆压缩、标题生成这类后台请求），
它们拿到 SSE 文本再 `JSON.parse`，就炸了。

## 修法：按调用方要的模式返回

```js
var wantStream = !!obj.stream;   // 先记住调用方要什么
obj.stream = false;              // 请求上游时仍然非流式（为了拿完整 JSON、丢思考链）

function reply(text) {
  var t = ppCleanContent(text);
  if (wantStream) return ppSSEResponse(t);       // 要流式 → 合成 SSE
  return ppJSONResponse(200, {                    // 要非流式 → 标准 JSON
    id: 'pp-...', object: 'chat.completion', model: obj.model,
    choices: [{ index: 0, message: { role:'assistant', content: t }, finish_reason:'stop' }]
  });
}
```

三处出口（流式响应 / 普通响应 / 原生 HTTP 兜底）全部走 `reply()`。

## 现在的行为矩阵

| 调用方 | 上游请求 | 返回给 App |
|---|---|---|
| 主对话（stream:true） | 非流式 | 合成 SSE，逐字显示 |
| 自动摘要 / 记忆 / 标题等（stream:false） | 非流式 | 标准 JSON |
| 思考链 | — | 一律剔除（`reasoning_content` 丢弃、`<thinking>` 等标签清除） |

## 说明
这条只管**官方 api.deepseek.com 直连**的情况；第三方中转若有特殊格式，另说。
