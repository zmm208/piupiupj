# v3.0 备份五项问题修复

## 1. 手动备份改为「清空重来」
之前手动备份是把新数据**叠加**到旧备份上，旧段不会消失。
现在 `bkBackupAll(true)` 先把内存里的段表清空，再整份采集、整份落盘。

## 2. 同一张卡不会重复备份
- 角色按 `roles.id` 去重
- 对话按 `chat_sessions.id` 去重
- 卡片各自独立成段 `card:<id>`，天然按 id 唯一

## 3. 聊天（回忆页）恢复不回来
三个原因叠加，全部改掉：

| 原因 | 修复 |
|---|---|
| 批量 INSERT 一次塞 80 行，`message_json` 很长时单条 SQL 过大，插件直接失败且被 catch 吞掉 | 改成**按体积分批**（单批 ≤180KB 且 ≤40 行），整批失败后**逐行重试**并统计失败数 |
| 回忆页使用 Pinia 分页缓存，恢复后仍读旧视图状态 | 恢复完成后清掉 `memory_view_state / chat_state / session_state / memoryPage` 等键，再 reload |
| `settings` **表**（SQLite 里的键值表）没备份 | 新增 `dbsettings` 段，表整体备份/恢复 |

恢复完成后会提示真实数量，例如：
```
恢复完成：12 卡 / 34 标签 / 8 对话 / 1560 消息 / 21 文件
```
数量为 0 就说明这一段没写进去，能立刻定位。

## 4. 角色卡展示图恢复后损坏
原因：之前用 `Filesystem` 插件写 `file://` 绝对路径，插件对绝对路径支持不稳，写入失败但被静默忽略。

修复：改由**原生 Java 直接读写文件**
```java
BackupStore.readFileB64(act, path)   // file:// 自动剥离；相对路径依次在
BackupStore.writeFileB64(act, path)  // filesDir / externalFilesDir / dataDir 下解析
```
- 先写 `.pptmp` 再 rename，避免半写坏图
- 单文件 12MB 上限
- 路径解析顺序：绝对路径 → `filesDir` → `externalFilesDir` → `dataDir`
