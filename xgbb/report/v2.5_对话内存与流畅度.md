# v2.5 对话闪退 / 卡顿 / 掉帧 处理记录

## 一、官方逻辑审计（先说结论）

| 组件 | `onUnmounted` / `onBeforeUnmount` | 说明 |
|---|---|---|
| `ChatView`（408 KB） | **0 个** | 组件销毁时不做任何清理 |
| `Live2DViewer`（18 KB） | **0 个** | 有 `destroy()` 方法，但没有生命周期钩子去调用 |
| `ChatroomContent`（128 KB） | **0 个** | 有 1 个 `setInterval` 没有对应清理 |

也就是说：**快速打开多个对话再退出，blob URL、PIXI 纹理、Live2D 画布都不会被回收**。
每个对话都会加载角色头像/背景（blob URL）+ Live2D 贴图，几次之后 WebView 堆内存飙到 OOM → 闪退。

## 二、加了什么

### 1. 离开对话页立即释放内存
监听 `pushState / replaceState / popstate / hashchange`（外加 1.5s 兜底），
从 `/chat` 或 `/chatroom` 切走时执行 `releaseChatMemory()`：

1. **回收全部 blob URL**（角色头像/背景大图都走 `URL.createObjectURL`）
   - 同时给 `URL.createObjectURL` 打了记录钩子，最多保留 60 个，超出自动回收最旧的
2. **清 PIXI / Live2D 纹理缓存**
   - `PIXI.utils.clearTextureCache()`
   - 逐个 `TextureCache[k].destroy(true)` 并删除
   - 逐个 `BaseTextureCache[k].destroy()` 并删除
3. **清理残留画布**：`#live2d canvas / .live2d-canvas / canvas[data-live2d]` 宽高置 0 后移除
4. 清我们自己的缓存（AI 创建判定等）

### 2. 内存压力保护
每 8 秒检查 `performance.memory.usedJSHeapSize`，在对话页且超过 **260 MB** 时主动释放一次。
→ 即使官方组件不清理，也不会一路堆到崩溃。

### 3. 打开对话更快
- 构建时在 `index.html` 注入 **ChatView 分包预取**：
  ```html
  <link rel="prefetch" href="/assets/c/ChatView-legacy-Dhvgx1FR.js" as="script" fetchpriority="high">
  ```
  408 KB 的主分包提前进缓存，点进对话不再现下载

### 4. 掉帧优化（60fps）
- 扫描触发从 `click / touchstart / touchend / keydown / input / scroll` **精简为前三个**
  → 打字、滚动不再触发任何全页查询
- 扫描任务按路由收敛：
  - `syncLoginUi()` 只在设置页（或存在 `.logout-item`）时执行
  - `hideFakeCardKey()` / `validateCardOnConnection()` 只在连接页执行
- 逐字输入、上下快速滑动时，主线程不再有我们注入的额外工作
