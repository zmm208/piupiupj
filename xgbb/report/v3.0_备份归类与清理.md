# v3.0 备份六项修复（聊天被当卡 / 删除策略 / 选择性恢复 / 去重 / Live2D）

## 1. 聊天被识别成角色卡、恢复后聊天空白
两个原因：
1. **旧备份里没有 `kind` 字段**，恢复只能靠段名前缀猜，边界情况会错位
2. **孤儿会话**：官方 PiuPiu酱 卡被排除在备份外，但它的聊天被备份了；
   恢复后会话的 `role_id` 指向不存在的角色 → App 关联不上 → 显示空白甚至被当成卡

修复：
```js
// 备份：只备份"角色卡也在备份里"的聊天
if (!roleIds[String(d.session.role_id)]) return;
// 恢复：跳过 role_id 不在本次恢复角色集合里的会话
sessions = sessions.filter(s => roleIdSet[String(s.role_id)]);
// 每个段写入 kind: 'card' / 'chat'，恢复时优先按 kind 分流
```

## 2. 不再自动同步删除备份
删掉了「检测到删除 → 询问同步删备份」的逻辑（函数保留但不再触发）。
App 里删角色/聊天，备份**保持原样**。

## 3. 备份自动过期：一周未变动自动清理
- 每次写入段时记录时间戳（`meta` 段，加密存储）
- 启用备份时、每次备份完成后检查
- 只清理 `card:*` / `chat:*`：超过 **7 天**没更新的直接删除
- **配置类（预设 / API / 卡密 / 世界书 / dbsettings）永不清理**

## 5. 重复函数清理
脚本里几乎所有函数都被**整段复制过一遍**（历史补丁叠加导致）。
用大括号匹配逐个比对函数体：
- 删除 **85 个**逐字节相同的重复定义
- 4 个内容不同的（`bkUpsertBatch` / `ppDeviceId` / `releaseChatMemory` / `watchRoute`）人工判定后保留新版
- 文件从 4616 行 → **3400 行**，JS 从 229 KB → **164 KB**

## 6. 主页 Live2D 不显示
真因：`releaseChatMemory()` 里调用了
```js
PIXI.utils.clearTextureCache();
TextureCache[k].destroy(true);
BaseTextureCache[k].destroy();
```
主页和聊天页**共用同一套 PIXI 贴图**，退出聊天时把缓存全销毁 →
回到主页模型贴图缺失，看起来就是"模型不显示了"。

修复：**彻底移除 PIXI 纹理销毁**，只保留：
- 回收 blob URL
- 清理聊天容器内残留画布（限定 `.chat-view / .chat-container`，不再全局删 canvas）
