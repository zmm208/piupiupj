# v3.0 启动失败（无法连接服务器）修复

## 真因
`piupiu-guard.js` 里 **fetch 包装被复制成了两份**：
第二份的 `var of = window.fetch.bind(window)` 抓到的已经是第一份的包装函数，
两个包装互相调用 → `Maximum call stack size exceeded`。

App 启动时会拉取必要配置，这个异常被它的启动 try/catch 捕获，
于是弹出「连接失败 · 无法连接服务器获取必要配置」。

浏览器实测（注入守卫后）：
```
修复前: fetch('/version.json') → ERR: Maximum call stack size exceeded
修复后: fetch('/version.json') → 200
        跨域请求             → 404（服务端真实应答，无递归）
```

## 修复
1. 删除重复的 fetch 包装块（`ppFetch` / `ppFetchWrapped` / `installFetch` 各只保留一份）
2. `ppFetchWrapped` 全程 try/catch：我们内部任何异常都退回原生 `fetch`，绝不把异常抛给 App
3. `Storage.getItem` / `setItem` 覆盖整体包 try/catch，出错走原始实现
4. 备份模块默认**关闭**（`pp_backup_on`），设置卡里手动开启后才读写文件
   - 自动备份定时器延后 15 秒启动
   - DNS 竞速延后到 6 秒
5. 备份入口全部先判断开关，未开启时完全不碰原生存储

## 验证
```
签名 verified=true / v2=true / v3=true
ppFetch 定义数: 1
ppFetchWrapped 定义数: 1
浏览器: 首页正常渲染、相对/跨域 fetch 均正常
```
