# v3.0 换包名：与官方版共存

## 改动

| 项 | 原值 | 新值 |
|---|---|---|
| **applicationId（包名）** | `io.piupiu.chat` | **`io.piupiu.pj`** |
| FileProvider authority | `io.piupiu.chat.fileprovider` | `io.piupiu.pj.fileprovider` |
| androidx-startup authority | `io.piupiu.chat.androidx-startup` | `io.piupiu.pj.androidx-startup` |
| Capacitor appId | `io.piupiu.chat` | `io.piupiu.pj` |
| custom_url_scheme | `io.piupiu.chat` | `io.piupiu.pj` |
| package_name | `io.piupiu.chat` | `io.piupiu.pj` |
| 桌面名称 | `PiuPiu酱` | **`PiuPiu酱·插件版`** |

## 为什么不改类名
`package` 只决定 applicationId（安装身份），组件里写的是**绝对类名**：

```
io.piupiu.chat.MainActivity
io.piupiu.chat.KeepAliveService
io.piupiu.chat.guard.GuardApp
io.piupiu.chat.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION
```

这些类名仍然指向 dex 里真实存在的类，保持不变；只把 `package="…"` 换成新值，
系统就把两者当成两个独立 App —— **可以同时安装、同时运行**。

## 必须改的 authority
Provider 的 authority 是**全设备唯一**的，如果两个 App 都用
`io.piupiu.chat.fileprovider`，第二个会安装失败（INSTALL_FAILED_CONFLICTING_PROVIDER）。
所以两个 authority 都改成了 `io.piupiu.pj.*`。

Capacitor 的 FileProvider 调用用的是 `context.getPackageName() + ".fileprovider"`，
包名一变它自己就算成 `io.piupiu.pj.fileprovider`，与新的 authority 自动对上。

## 密钥兼容（重要）
设备指纹原来包含包名，换包名会导致**旧备份解不开**。已处理：

- 新指纹**不再包含包名** → 以后再换包名密钥也不变
- 解密时先试新密钥，失败再用「旧包名 `io.piupiu.chat`」参与指纹的老密钥重试一次
- 所以之前用 `io.piupiu.chat` 版生成的备份，在新包里仍能读出来

## 注意事项
1. **数据不共享**：新包名 = 全新数据目录，首次打开是空账号、空聊天。
   想搬数据：旧版里「立即备份」→ 新版里「恢复备份」（同一个 `/storage/emulated/0/piupiupj/piupiupj.json`）
2. 两版可以同时在线，互不干扰；官方版的聊天/卡不会再被插件版影响
3. 备份目录两者共用，注意别互相覆盖（插件版写的是同一份文件）
