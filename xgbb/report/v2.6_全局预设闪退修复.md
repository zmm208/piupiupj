# v2.6 全局预设连点闪退：病因与修复

## 病因（源码取证）

`updateGlobalPresetItem`（预设 store）：

```js
updateGlobalPresetItem(id, name, preset) {
  const cur = await Fe(id);              // 从存储读整份预设
  let p = Nu(preset);                    // 规范化（深拷贝 + 遍历所有 prompt）
  const remote = await ki(cur);          // 再读一份对比
  p = Ci(p, remote);                     // 合并
  await Ae([{ id, preset: p }], [], () => { ... });   // 序列化落盘
  i.set(id, { updatedAt, preset: Fu(p) });            // 再压一份进缓存
}
```

一次点击的状态：
- `presets/default-global-preset.json` 是 **1,227,278 字节（1.2 MB）**
- `Nu / Ci / Fu / ki` 每个都会做深拷贝或全量遍历
- `Ae` 会 `JSON.stringify` 整份预设再写 localStorage

**连点三下 = 三份 1.2 MB 的字符串同时在堆里 + 三次全量遍历**，
WebView 堆瞬间冲高，加上切换时旧的引用还没释放 → OOM 闪退。
所以你观察到的规律（"多点几下再切其他的"）完全对得上。

## 修法（不动官方逻辑，只在边界上拦）

### 1) 连点防护（捕获阶段拦截，不到官方 handler）
```js
// 同一个预设 700ms 内重复点 → 吞掉
// 300ms 内连续切换不同预设 → 也吞掉
document.addEventListener('click', handler, true);
```
只拦"同一排/同一按钮"的重复点击和极速切换，
正常点一次、隔一会儿换一个，完全不受影响。

### 2) 大对象写去重
```js
Storage.prototype.setItem = function (k, v) {
  if (typeof v === 'string' && v.length > 120000) {
    if (k === LAST_BIG_K && v === LAST_BIG_V) return;  // 内容一样就不重复落盘
    LAST_BIG_K = k; LAST_BIG_V = v;
  }
  ...
};
```
同一份 1.2 MB 内容重复写多次时，只有第一次真正落盘；
字符串比较是内存级操作，比"序列化 + 写盘"便宜一个数量级。
只保留**最后一组**键值引用，不会无限占内存。

## 覆盖范围
- 全局预设（主因）
- 全局正则 / 全局世界书（同样走大对象存储，一并受益）

## 仍建议用户这样用
切换预设后停 0.5 秒再切下一个 —— 现在连点已经被吞掉，但官方本身每次切换都要
重新序列化 1.2 MB，物理上就是有开销。
