# v3.0 备份补全：图片本体 + 媒体本体 + 变动检测

## 1. 角色卡图片（二进制本体）
- `roles.image_path` → `Capacitor.Filesystem.readFile` 读成 base64
- 每张卡单独一个段：`card:<id>` = `{ row: {...}, image: "<base64 PNG>" }`
  - 单独成段的目的：改一张卡只重加密那一段，其余段原样保留
  - 图片是原始 PNG 字节，含 `tEXt` 里的 `chara`（v2 卡数据），恢复后能原样再导入
- 单文件上限 12 MB（base64 后约 16.8 MB），超过跳过并在结果里可知
- **官方默认卡不导出**：`is_official = 1` 或 `role_name` 含 `PiuPiu/piupiu` 的跳过

## 2. 聊天媒体（图片 / 语音本体）
`chat_media_refs.path` 逐条读文件，塞进对应 `chat:<id>` 段：

```json
{ "session": {...}, "messages": [...],
  "media": [ { "path": "...", "kind": "message", "index": 3, "data": "<base64>" } ] }
```

恢复时 `Filesystem.writeFile({path, data, recursive:true})` 写回原路径。

## 3. 数据变动检测
每 20 秒（页面可见时）比对一次签名：

```sql
SELECT count(*), max(updated_at) FROM roles
SELECT count(*), max(id) FROM chat_sessions
SELECT count(*), max(timestamp) FROM chat_messages
SELECT count(*) FROM chat_media_refs
```

签名变了 → 触发一次备份；同一时间只跑一个备份任务（`BK_SIG_BUSY` / `BK.busy` 双锁）。
叠加原有的两个触发点：
- 退出某个对话 → 只备份 `chat:<id>`
- 改 API / 预设配置 → 1.2 秒防抖后备份 `settings` + `api`

## 4. 段结构（v3.0）

```
cards          世界书 / 角色标签 / 角色 id 索引
card:<id>      单张角色卡（DB 行 + 原始 PNG）
chat:<id>      单条对话（session + 消息 + 媒体文件本体）
settings       全部 piupiu_* 本地配置
api            自定义模型 / 当前模型 / 渠道开关
vip            仅真卡密
```


## 6. 内存控制
- 单文件 12 MB 上限
- 段级加密：只重算变化的那一段
- 原生分块写（64 KB/次），临时文件 + rename
- 恢复/备份结束后清空引用
