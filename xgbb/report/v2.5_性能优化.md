# v2.5 性能优化记录

## 病症
整个 App 明显卡顿，尤其**收到 AI 回复瞬间会卡一下**。

## 根因（都是注入层，不是官方代码）

| # | 问题 | 为什么卡 | 位置 |
|---|---|---|---|
| 1 | `document.body.innerText` | 每次调用强制同步布局并抽取全页文本；原来每秒 + 每次请求都会调 | `aiCreateOpen()` |
| 2 | 每秒一轮全页 `querySelectorAll('input,div,section,form')` | 消息越多节点越多，1000ms 一次全量扫 | `attachAuthClose` / `findUpdateCard` |
| 3 | 每 250ms 一次选择器轮询 | 与上一条叠加，空闲时也在烧 CPU | `injectPickerModels` |
| 4 | 流式请求 `r.clone().text()` | 破甲分支对 `stream:true` 也做克隆+整段读取，等于把 SSE 全量缓存后才放行 → 回复到达时明显顿一下 | fetch 钩子 |
| 5 | 启动即打 7 个 DoH + GitHub API | 跟首屏抢带宽和主线程 | `dnsRace` / `checkUpdate` |
| 6 | `paintChip` 每次点击都重写 `style.cssText` | 触发样式重算 | 破甲胶囊 |

## 改法

1. `aiCreateOpen()` 改为**一次 `querySelector('.steps[aria-label="创作流程"]')`**，结果缓存 600ms
2. 轮询彻底删掉，换成**事件驱动调度器** `scheduleScan()`：
   - 监听 `click / touchstart / touchend / keydown / input / scroll`（capture + passive）
   - 监听 `hashchange / popstate / visibilitychange`
   - 120ms 防抖，页面 `hidden` 时直接跳过
   - 仅保留一个 **5 秒**兜底扫描
3. 各注入函数加廉价门禁：`hasModalish()`（3 次 querySelector）、`.piupiu-chat-input-wrapper`、`.steps`、设置页路径判断
4. 流式请求：识别 `stream:true` 后**直接放行不再 clone**，破甲提示词照样注入，只是不做拒答重试
5. 启动网络任务改 `requestIdleCallback`：DNS 竞速延迟 2.5s、更新检查延迟 4s
6. `paintChip` 增加状态缓存，状态未变不写样式
7. 去掉 `backdrop-filter: blur()`（移动端合成开销大）

## 预期效果
- 空闲时 CPU ≈ 0（原来每秒一次全页扫 + 每 250ms 一次）
- 流式回复不再二次缓存，首字到达即渲染
- 首屏不再被 7 个 DoH 抢占
