# v2.5 「Connection reset」修复：端点被拼了两次

## 直接原因

`applyCustom()` 已经把 Base URL 拼成完整端点：
```
https://你的中转/v1/chat/completions
```
`ppSendCustom()` 里又拼了一次：
```
cu.url.replace(/\/+$/, '') + '/chat/completions'
→ https://你的中转/v1/chat/completions/chat/completions     ← 404 / 连接被重置
```
所以服务端直接掐断连接，App 收到 `Connection reset`。

## 修法

### 1) 端点统一由 `cuEndpoint()` 生成
```js
function cuEndpoint(base) {
  var b = String(base||'').trim().replace(/\/+$/, '');
  if (!/\/chat\/completions$/i.test(b)) b += '/chat/completions';
  return b;
}
```
- `https://x/v1` → `https://x/v1/chat/completions`
- `https://x/v1/chat/completions` → 原样返回（不会再叠加）
- 三处调用（正式对话 / 测试对话 / AI 创建）全部改用这个函数

### 2) 原生 HTTP 失败自动回退
```js
http.request(...).catch(e => fetch(...))   // 原生失败再试一次普通 fetch
```
超时也调整：连接 20s、读取 180s（长回复不会被掐）。

## 关于「只需要替换发送者」

你理解的逻辑就是现在的逻辑：

| 环节 | 谁做的 |
|---|---|
| 组装上下文（历史 / 记忆 / 忆境典藏 / 回忆视界 / 世界书 / 角色卡 / 用户人设 / 预设） | **官方代码原样执行** |
| 决定用什么模型 | 你把聊天模型切到自定义（`S.curId` + `customOn`） |
| 把这条已经组装好的请求发到哪 | 我们只改 **URL + Authorization** |
| 回复渲染（流式逐字 / 入库 / 重试） | 官方代码原样执行（我们把非流式结果合成为 SSE 流喂回去） |

`messages` 数组我们一个字段都不改；破甲词是**合并**进已有的 system，
不会覆盖记忆和预设。
