# v2.5 自定义对话立刻 reset：真因是"原生 HTTP"那条路

## 你的两个关键信息
- Base URL：`https://api.deepseek.com`
- **测试对话能通，真实对话一按就 reset**

→ 说明请求体、Key、URL 全是对的；差的只是**发送通道**。

## 为什么测试能通、真实对话不行

| 路径 | 通道 | 结果 |
|---|---|---|
| 测试对话（`send()`） | 普通 `fetch` | 通 |
| 真实对话（`ppSendCustom` 旧版） | **CapacitorHttp 原生** | 立刻 reset |

上一版我把真实对话改成了原生 HTTP（为了绕 CORS），结果这条路在你这台设备上直接失败；
测试对话仍然是 fetch，所以它一直好使。

## 现在的实现

```
真实对话 = 和测试对话完全同一条 fetch 通道
         ↓ 只有网络层失败（CORS/reset）才回退 CapacitorHttp
```

```js
of(window, cu.url, { method:'POST', headers:{Authorization:'Bearer '+key}, body })
  .then(r => r.ok ? r : 抛出 HTTP 错误)     // 4xx/5xx 直接报给用户，不重试
  .catch(e => 非 HTTP 错误 → 原生 HTTP 再试一次)
```

- 流式：直接返回原始 `Response`，App 的 SSE 解析、逐字渲染照旧
- 非流式：原样返回
- 破甲：合并进已有 system（不覆盖记忆/预设/角色卡）
- `messages` 一个字段都不改 —— **上下文就是官方拼好的那一份**
