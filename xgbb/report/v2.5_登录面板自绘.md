# v2.5 登录面板改为自绘（不再依赖 App 内部弹窗）

## 为什么之前点登录没反应
App 的登录弹窗由根组件的 `W.value` 控制，只有 `Ae()` 能打开它。
原生的「会话失效」事件链 `$e()` 会先弹「登录已失效，请重新登录」，再调 `Ae()`；
在真机上这条链并不会稳定打开弹窗（会先被会话状态覆盖），所以你只看到提示文字。

## 现在怎么做的

### 1. 自绘登录面板（`#pp-loginsheet`）
- 样式对齐官方：白卡 / 圆角 22 / 粉色主色 `#e97998`，暗色下 `#1a1b21`
- 字段：邮箱、密码；错误行；`×` 关闭
- 点击直接打开，不经过 App 的任何内部状态

### 2. 走官方接口
```
POST https://www.piupiuchan.top/account_auth.php
1) {action:"issue_login_captcha", email}                     → challenge_id + track_image
2) {action:"verify_login_captcha", challenge_id, slider_position,
    drag_duration_ms, drag_trace:[{x,y,t}]}                   → verify_token
3) {action:"login", email, password, device_id,
    captcha_verify_token}                                     → access_token / expires_at / user / device_id
```
（字段名与 App 内部 `issue_login_captcha` / `verify_login_captcha` / `login` 完全一致）

### 3. 人机验证（滑块）
- 显示 `track_image`（服务端 BMP，280×92）
- 中间一条粉色竖线跟随拖动，拖到缺口位置松手
- 松手后记录轨迹并提交，通过则继续登录

### 4. 登录成功
写入官方会话格式：
```json
{"accessToken":"...","expiresAt":"...","user":{"id":1,"email":"..."},"deviceId":"..."}
```
派发 `piupiu:account-session-changed`，然后 `location.reload()` —— App 会按已登录状态重新初始化，
「登录」按钮自动变成「退出登录」。

## 浏览器实测
```
点「登录」          → 面板打开（邮箱/密码/×）
填账号点登录        → 出现滑块验证（图片 280×92，拖动条 + 竖线）
verify_login_captcha → 服务端正常响应（challenge 过期返回“验证挑战不存在，请重新获取”）
```

## 顺带修掉的
- `customOn` 未定义导致聊天拦截分支整段失效（这就是「请先激活专属通道」的真因）
- 连接中心卡密输入框不再显示假卡密（读取按调用栈过滤 + 启动清理 + 进页面校验）
