# v2.5 自定义模型：回复不显示 / 官方上下文失效 修复

## 一、为什么「自定义 AI 回复没有」

两个原因叠在一起：

### 1) 破甲把官方 system 整段删掉
旧实现：
```js
j.messages = j.messages.filter(m => m.role !== 'system');   // ← 清空所有 system
j.messages.unshift({ role:'system', content: armorPrompt }); // ← 只留破甲词
```
App 拼好的 **记忆 / 预设 / 世界书 / 角色卡 / 用户人设** 全在 system 里，
被这一行全删了 → 模型既没有上下文，也拿不到任何 VIP 本地能力的产物；
表现为"答非所问 / 像没回复"。

### 2) WebView 的 CORS 拦住了第三方中转
`fetch` 从 `capacitor://localhost` 发到你的中转域名，中转多半不回 CORS 头 →
请求在浏览器层就被拦，App 收到的是网络错误，界面上就没有回复。

## 二、现在的做法（只换"发给谁"，其它一律不动）

### 1) 走原生 HTTP，绕开 CORS
```js
const http = window.Capacitor?.Plugins?.CapacitorHttp;
http.request({ url, method:'POST', headers:{Authorization:'Bearer '+key}, data: obj });
```
- 原生层发请求，不受同源策略限制
- 强制 `stream:false`（原生 HTTP 不做 SSE），拿到完整文本后**合成为 SSE 流**回给 App：
  ```
  data: {"choices":[{"delta":{"content":"…"}}]}
  data: [DONE]
  ```
  所以 App 的流式渲染、逐字效果、消息入库逻辑全部照旧
- 非流式请求则返回标准 `choices[0].message.content` JSON

### 2) 上下文一字不改
`applyCustom()` 只替换 `model`，`messages` 完全保留；
`Authorization` 换成你的 key；官方头（`X-PiuPiu-*`）不再携带。

### 3) 破甲改为"合并"而不是"替换"
```js
// 找到已有的 system（就是 App 拼的记忆/预设/角色卡）
j.messages[idx] = { role:'system', content: armorPrompt + '\n\n' + 原文 };
// 没有 system 才新建
```
→ 官方 VIP 本地功能（忆境典藏 / 回忆视界 / 自动摘要 / 保留完整上下文 / 预设 / 世界书）
的产物**完整送到 AI**，破甲词只是前面加一段。

## 三、效果对照

| 场景 | 之前 | 现在 |
|---|---|---|
| 自定义模型回复 | 经常空白 | 原生 HTTP 发送 + 合成 SSE，正常逐字显示 |
| 记忆 / 预设 / 角色卡 | 被破甲删掉，AI 收不到 | 完整保留并与破甲共存 |
| 世界书 / 用户人设 | 同上 | 同上 |
| 官方模型 | 不受影响 | 不受影响（只有自定义分支走新路径） |
| 测试对话 | 之前被改写 | 带 `X-PP-Test` 标记，直接放行 |
