# v3.0 恢复弹窗卡死 + 无法解密

## 一、点「恢复备份」卡出一个灰色空白弹窗

**原因**：弹窗打开时把所有段**同步解密**了一遍（每张卡还带一张 base64 图），
几百 KB～几 MB 的 GCM 解密 + JSON.parse 全堆在主线程，
WebView 直接卡住 —— 遮罩已经显示、内容还没渲染，就是"灰色空白"。

**修复**：
- 弹窗只读段名和时间戳，**完全不解密**
- 列表显示「角色卡 #id / 聊天 #id + 备份于 …」
- 勾选后点「合并/覆盖」才进入恢复流程（恢复里本来就逐段解密）

浏览器实测：打开弹窗 **405 ms**，正常渲染，内容完整。

## 二、查看备份「无法解密」与卡顿

同样是一次性解密导致的问题，改成**渐进式**：

- 打开查看器只渲染骨架（名字 + 备份时间 + 占位「…/加载中…」）
- 每 16 ms 解密一条并就地填充 DOM
- 角色卡：先出「角色卡 #id」，解密完成后替换成封面图 + 完整信息
- 聊天：先出「聊天 #id」，解密后补上所属角色名、消息数、媒体数
- 其他：先出板块名，解密后填入 JSON
- 单条解密失败只在该条标「无法解密」，不影响整个页面

浏览器实测：查看器打开 **504 ms**，零 JS 报错。

## 三、无法解密本身

两件事：

1. **换包名前生成的备份**：设备指纹原来包含包名，换包名后密钥变了。
   `BackupStore.decrypt()` 现在会**先用新密钥、失败再用旧包名 `io.piupiu.chat` 的密钥重试一次**，
   AAD 里的 keyId 也按对应指纹计算。旧备份应该能正常读出。
2. **真的解不开**（文件被覆盖/损坏/别的设备）：那条会标「无法解密」，
   不会卡住，也不会影响其它条目。

## 四、以后的打包方式（已固化进 build.py）

每次构建自动执行：

```
patch_package_assets()   capacitor appId / strings.xml → io.piupiu.pj，app 名 → PiuPiu酱·插件版
patch_manifest()          package → io.piupiu.pj，authorities → io.piupiu.pj.*
                         + MANAGE_EXTERNAL_STORAGE、requestLegacyExternalStorage、GuardApp
prune_live2d()           删 live2d 资源与 pixi/cubism 库
```

包名替换用 `rename_package()`，改的是 `<manifest package="…">` 与两个 provider authority，
**类名保持 `io.piupiu.chat.*` 不动**（dex 里就是这些类），所以能与官方包共存。
