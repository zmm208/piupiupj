# v3.0 聊天扫不到 + Live2D 仍不显示

## 一、聊天内容扫不到（改用直接读数据库文件）

### 为什么之前扫不到
备份原来走 CapacitorSQLite 插件的 `query()`。插件要求连接处于打开状态、
且连接名/参数与 App 内部一致；一旦不满足，`query` 直接失败，而我们的 `catch` 把它变成空数组
—— 于是"备份成功"但里面没有聊天。

### 现在怎么做
新增原生直读，不再依赖插件：

```java
BackupStore.dbDump(act)   // 找到 /data/data/io.piupiu.chat/databases/*.db
                          // SQLiteDatabase.openDatabase(..., OPEN_READONLY)
                          // 逐表 SELECT * → 自定义分隔符格式
BackupStore.dbExec(act, joined)  // 恢复时开事务、关外键、批量执行
```

- 查找顺序：`databases/piupiuSQLite.db` → `piupiu.db` → 目录下任意 `.db`
- 导出表：`roles / role_tags / world_books / world_book_entries / chat_sessions / chat_messages / chat_media_refs / settings`
- 聊天按 `chat_sessions.id` 分组，消息按 `session_id` 归属，媒体按 `owner_id` 关联并读出文件本体
- 备份失败时会明确提示，不再静默变成空备份

### 恢复
- 原生可用时：一次性拼 SQL，交给 `dbExec` 在事务里执行（关外键 → 写 → 开外键）
- 原生不可用时：退回插件批量写（原有逻辑）
- 恢复后清视图缓存并重载

## 二、Live2D 仍不显示

上一版只删了 PIXI 纹理销毁，但 `releaseChatMemory()` 里还有两件事在破坏资源：
1. `URL.revokeObjectURL()` 回收 **所有** blob URL —— Live2D 贴图/模型资源如果是从 blob 加载的，被 revoke 后模型就白了
2. `[class*="chat"] canvas.live2d` 选择器过宽，主页容器类名里含 "chat" 时会被一起删掉

现在 `releaseChatMemory()` **只清我们自己的缓存**，blob URL、PIXI 贴图、canvas 一律不动。
内存交给浏览器的 GC 和 App 自己的生命周期处理。

## 测试建议
1. 打开「启用备份」→「立即备份」，看提示的数量（应当 > 0）
2. 「查看备份内容」里应有角色卡与聊天条目
3. 删除一个聊天后「恢复备份」，勾选它再恢复
4. 进出聊天页几次，回主页看 Live2D 是否还在
