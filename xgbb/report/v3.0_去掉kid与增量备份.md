# v3.0 去掉 kid + 增量自动备份

## 1. 为什么 json 里有 `"kid":"fa8f3944677c83ea"`

那是我为方便排查写在文件头里的**设备密钥标识**（64 位密钥的十六进制形式）。
它本身不是密钥，但它由设备指纹派生，属于可识别信息 —— 与"加密保护隐私"的目的相悖。

已移除：
- 文件头不再写 `kid`，现在是
  ```json
  {"v":2,"ver":"3.0","updatedAt":1732…,"sections":{ … }}
  ```
- 界面上原来的「备份（设备密钥 fa8f3944）」改成 **「备份（已加密）」**
- 恢复弹窗里的 `设备密钥 xx` 一行也去掉了

旧备份文件里残留的 `kid` 字段不会影响读取（解析时忽略），下次写入就会被覆盖掉。

## 2. 自动备份（增量，不删同步）

每 15 秒检查一次数据库（页面可见、备份已启用时）：

| 变化 | 动作 |
|---|---|
| 出现**新角色卡**（或 `updated_at` 变化） | 只备份这一张 `card:<id>`（含原图） |
| 出现**新对话**（或 `updated_at` 变化） | 只备份这一条 `chat:<id>`（含消息 + 媒体） |
| **删除**角色卡 / 对话 | **什么都不做**，备份保持原样 |

补充：
- 首次运行只建立基线（记下现有 id 与更新时间），不会一次性刷几百条
- 退出对话时会额外触发一次该对话的备份（`route leave` 钩子）
- 只写变化的段，其它段原样保留

## 3. 仍然生效的旧规则
- 手动「立即备份」= 清空重来
- 「修复聊天消息」按钮：会话在、消息缺时用 `session_json.messages` 补写
- 超过 7 天没变动的 `card:*` / `chat:*` 自动清理（配置类永不清理）
- 恢复时勾选要恢复的角色卡与聊天，其余段自动全恢复

## 验证
```
签名 verified=true / v2=true / v3=true
文件头 kid: 已无
UI kid 展示: 已无
增量备份（BK_CARD_SEEN / BK_CHAT_SEEN）: 在
```

## 说明
`kid` 移除后，跨设备恢复的判断只能靠"解密是否成功"：
密钥不对时 `backupDecrypt` 返回空，会提示「备份解密失败（密钥不匹配或文件损坏）」。
