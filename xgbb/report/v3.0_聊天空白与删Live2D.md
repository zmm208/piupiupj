# v3.0 聊天空白修复 + Live2D 彻底删除

## 一、点开对话是空白

`ChatView` 读消息：

```sql
SELECT message_index, message_id, role, content,
       json_extract(message_json,'$.speakerName') AS name,
       json_extract(message_json,'$.swipe_id')    AS swipe,
       json_type(message_json,'$.image')          AS image
FROM chat_messages
WHERE session_id = ? AND message_index >= ? AND role IN ('user','assistant')
ORDER BY message_index
```

会话能点开说明 `chat_sessions` 在，空白说明 `chat_messages` 没读到行。

### 这版新增

**1. 恢复后自动补消息**
恢复完成后会重新 dump 数据库：如果「会话数 > 0 但消息数 = 0」，
立刻用每个会话的 `session_json.messages` 反推出消息行写回，然后再重载。

**2. 手动「修复聊天消息」按钮**
扩展功能卡里新增，随时可点。逻辑同上，但会逐会话检查
（`message_count` 与实有行数比对），缺的补、多的删了重建。

**3. 消息行字段规范化**
`role` 归一成 `user / assistant / system`；`message_id` 缺失就补 `m<index>`；
`content` 缺失时从 `text` 兜底；`message_json` 用原始对象序列化，保证
`json_extract` 能取到 `speakerName / swipe_id / image`。

**4. 原生写库失败自动回退插件路径**
数据库被 App 占用时 `dbExec` 会返回 false，这时自动改走
`INSERT OR REPLACE` 逐表写，两条路都试完才报失败。

**5. 恢复提示带真实落库数量**
```
恢复完成：6 卡 / 5 对话 / 218 消息 → 库里现有 5 对话 / 218 消息
```

## 二、Live2D 彻底删除（省 6 MB）

构建阶段直接清理，不再只是隐藏：

| 删除项 | 说明 |
|---|---|
| `assets/public/live2d/**` | Hiyori 模型全套（model3/physics3/motions/贴图） |
| `assets/public/lib/pixi.min.js` | 476 KB |

| `index.html` 里的 `<link>` 预加载 | 逐行过滤掉 |

`Live2DViewer-legacy-*.js` 这个分包还留着（不被调用就不加载），
`html.pp-live2d-off` 的隐藏样式也保留，双保险避免出现空白区域。

## 建议操作顺序
1. 装新版 → 设置 → 扩展功能 → 开「启用备份」
2. 点 **「修复聊天消息」** ← 先修历史空白对话，看提示修了几个
3. 打开回忆页确认内容回来了
4. 再做一次「立即备份」，以后恢复就有完整消息了
